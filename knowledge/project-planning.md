# Planning portfolio projects that demonstrate skills

A good portfolio project demonstrates the specific skills your target role needs, and leaves verifiable evidence behind.

## Choose the project from your gaps

Start from your highest-priority skill gaps in the AI Career Guidance App. Pick a project that exercises two or three of them together. For example, a data-analyst candidate missing SQL and BI tools could build a dashboard on a public dataset, with the SQL used for data preparation.

## Break the project into milestones

1. **Problem statement** (half a page): who the user is, what problem is solved, and how you will know it works.
2. **Minimum viable version**: the smallest end-to-end slice that works, for example one page, one API endpoint, or one model with an evaluation.
3. **Quality pass**: tests, input validation, error handling and a README with setup instructions.
4. **Depth pass**: one feature that shows the target skill at the required level, such as deployment, a proper evaluation protocol, or a normalised schema.
5. **Write-up**: decisions, trade-offs, limitations and what you would do next.

Aim for each milestone to fit within one or two weeks of your available study hours.

## Make the evidence verifiable

- Keep the code in a version-controlled repository with meaningful commits.
- Include a README a reviewer can follow to run the project.
- Deploy it if the role values deployment (web, backend, ML engineering).
- In the AI Career Guidance App, add the project to your twin, link the skills it demonstrates at an honest level, and request verification from a mentor.

## Avoid common mistakes

- Starting with an over-ambitious idea that never reaches a working version.
- Copying a tutorial without adding your own design decisions.
- Claiming skills the project does not actually exercise.
- Never documenting limitations. Reviewers trust honest write-ups more.
